---
title: "Ave"
description: "Passkey accounts, OAuth 2.0 and OpenID Connect, and end-to-end encryption keys delivered to your app."
---

Ave is an identity provider for apps that need to be secure and end-to-end encrypted. Users sign in with a passkey, your app receives standard OpenID Connect tokens, and, when you ask for it, a per-user encryption key that only the user's device and your client code ever see in plaintext.

Ave's servers store encryption keys only in a form wrapped by the user's master key. The master key is unlocked on the user's device during sign-in, the app key is unwrapped in the browser, and it reaches your app in the callback URL fragment, which browsers never send to a server.

## What you get

  <Card title="End-to-end encryption keys" icon="lock" href="/guides/end-to-end-encryption">
    Request `e2ee:symmetric` for a per-user AES-256 key, or `e2ee:asymmetric` for a keypair plus public-key lookup so users can encrypt for each other.
  </Card>
  <Card title="Passkey accounts" icon="fingerprint" href="/reference/how-it-works">
    Passwordless sign-in, account recovery, and multiple identities per account. Your app never handles credentials.
  </Card>
  <Card title="Standard OAuth 2.0 and OIDC" icon="key" href="/guides/oauth-authorization-code-flow">
    Authorization code flow with PKCE, ID tokens, refresh token rotation, discovery, and JWKS.
  </Card>
  <Card title="Your app's structure" icon="users" href="/guides/app-authorization">
    Ave gives you a verified identity. Workspaces, membership, roles, and billing stay in your app.
  </Card>
</CardGroup>

## How an encrypted app uses Ave

<Steps>
  <Step title="Register your app">
    Create an app at [devs.aveid.net](https://devs.aveid.net) and register its callback URL. Every integration uses a registered client ID.
  </Step>
  <Step title="Ask for an encryption scope">
    Add `e2ee:symmetric` or `e2ee:asymmetric` to the scopes you request at sign-in. The consent screen tells the user that your app is end-to-end encrypted.
  </Step>
  <Step title="Receive the key with the tokens">
    `completeOAuthCallback` from `@ave-id/sdk/client` or the `onTokens` callback in `@ave-id/embed` hands you the tokens and the key together. The key comes from the URL fragment, not from the token endpoint.
  </Step>
  <Step title="Encrypt on the client">
    Encrypt user data with the key before it leaves the device. Your backend stores ciphertext and uses the verified `id_token` to decide who can read which rows.
  </Step>
</Steps>

The [Quickstart](/quickstart) walks through these steps with code.

## Hosts

| Host | Use it for |
| --- | --- |
| `https://aveid.net` | Sign-in and consent pages, OIDC discovery, JWKS |
| `https://api.aveid.net` | Token exchange, userinfo, public-key lookup |
| `https://devs.aveid.net` | Registering and managing apps |

<Warning>
  Send token requests to `https://api.aveid.net/api/oauth/token`. Users sign in on `https://aveid.net`.
</Warning>
